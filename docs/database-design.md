# データベース設計

## 1. 概要

メモをIDごとに管理


## 2. テーブル設計

### memosテーブル

| カラム名 | データ型 | NULL | 主キー | 説明 |
|---|---|---|---|---|
|id|TEXT|不可|○|メモを識別する一意のコード|
|title|TEXT|不可|  |メモのタイトル|
|memo_text|TEXT|不可|  |メモの本文|
|created_at|TEXT|不可|  |メモを作成した日時|
|updated_at|TEXT|不可|  |メモを更新した日時|


## 3. 設計理由

### id

IDはcrypto.randomUUID()にて採番するため、TEXT形式。メモの削除、更新等の際に一意に識別するため主キーとする。
主キーであるためNULLは不可。


### title

タイトルを文字列として保存するためTEXT形式。メモにはタイトルが必須であるためNULLは不可。


### memo_text

メモの本文を文字列として保存するためTEXT形式。メモ本文は必須であるためNULLは不可。


### created_at

メモを作成した日時(YYYY-MM-DD HH:mm:ss)を保存するためTEXT形式。メモを作成した日付を保持する必要があるため
NULLは不可。


### updated_at

メモの最終更新日時を記録するためTEXT形式。更新日時を利用した並び替えや、メモがいつ更新されたかの確認に利用する。
メモ作成時にも作成日時を更新日時として設定するためNULLは不可。


## 4. created_atとupdated_atを持つ理由

メモを作成した日時と更新した日時を別々に保持することで、作成日時でソート、更新日時でソートすることを可能にするだけでなく、
そのメモの作成日時と更新日時を比較することで編集有無の判定を行うことができる。
